Route Guards Testing & Feature Guide

1. How to Bypass CanActivate Initial Block

By default, navigation to the playground is blocked unless the user is logged in.

  1. Open Browser Developer Tools (F12 or Right-Click → Inspect).
  2. Navigate to the Console tab.
  3. Run the following command to set the login state: 
    localStorage.setItem('isLoggedIn', 'true');
  4. Verify the state anytime using:
    • localStorage.getItem('isLoggedIn'); — Returns 'true' or 'false'
    • localStorage.getItem('userRole'); — Returns 'admin' or 'user'
    • localStorage.getItem('betaFeature'); — Returns 'true' or 'false'

2. Guard Behaviors & Demonstration

CanActivate (Page Protection)

Triggers when clicking the Route Guards link from the home page. Blocks access and alerts if isLoggedIn is not 'true' in LocalStorage.

CanActivateChild (Nested Route Protection)

Inside the playground, click Child Route A or Child Route B. Requires userRole === 'admin' to proceed.

CanDeactivate (Unsaved Changes Warning)

Toggle the Form Has Unsaved Changes checkbox, then click Go Back Home. A browser confirmation dialog will prevent accidental navigation.

CanMatch (Dynamic Feature Flag Routing)

Click Feature Route. If betaFeature is enabled, Angular matches and loads BetaFeatureComponent. Otherwise, it falls back to StandardFeatureComponent.
